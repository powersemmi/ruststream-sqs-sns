# Партиции воркеров

Одна подписка читает одну очередь через одну задачу приёма, а `workers(n, by_key)` раскладывает её
сообщения по партициям воркеров, выбирая их по группе сообщений FIFO.

<Diagram name="lanes" words={words} />

Поток подписки выдаёт по одному сообщению. Без `workers` один цикл вызывает обработчик для каждого
сообщения по очереди, и ничего не выполняется параллельно. `workers(n)` выполняет до `n`
обработчиков одновременно, без определённого порядка.

`workers(n, by_key)` запускает `n` партиций воркеров, и сообщение попадает в ту партицию воркеров,
на которую указывает хеш его ключа. Ключ - заголовок
[`PARTITION_KEY_HEADER`](api:ruststream_sqs_sns::PARTITION_KEY_HEADER) сообщения, в котором хранится
его группа сообщений FIFO. Поэтому группа никогда не делится между двумя партициями воркеров, и
порядок, который [Группы](sqs/fifo.md) соблюдают в очереди, сохраняется и в сервисе. Если партиций
воркеров меньше, чем групп, каждая из них обслуживает несколько групп. У стандартной очереди групп
нет, поэтому у её сообщений нет ключа, и они по кругу расходятся по партициям воркеров.

Задача приёма опережает обработчики не больше чем на одно получение. Сообщение, которое она
получила, но ещё не выдала, тем временем остаётся невидимым благодаря продлению. Очередь FIFO
вдобавок придерживает группу, пока одно из её сообщений в обработке, поэтому следующее сообщение
группы не попадает в сервис, пока предыдущее не завершится или не истечёт его тайм-аут.

Несколько реплик сервиса или несколько подписок на одну очередь конкурируют за её сообщения: SQS
отдаёт каждое сообщение одной из них. Транспорт внутри процесса сохраняет порядок стандартной
очереди, а SQS нет, поэтому тест, который проверяет порядок, использует очередь FIFO.

[Обработчик пакетов](path.md) берёт по одному получению за раз, не больше размера, заданного в
точке монтирования, и не больше десяти, поэтому пакет часто меньше этого размера.
