# Чтение очередей

Это руководство читает очереди SQS: длинный опрос, тайм-аут видимости медленного обработчика, параллельные обработчики, пакеты и один обработчик на нескольких очередях.

Пример - сервис склада.
Он упаковывает заказы, проводит платежи и записывает изменения заказов.

Подписка опрашивает свою очередь длинным опросом через `ReceiveMessage`.
Каждый вызов ждёт сообщения до 20 секунд - дольше SQS не позволяет.
[`wait`](../components/subscriptions/wait.md) задаёт более короткое ожидание.
Очередь называют по имени или по URL, а имя разрешается через `GetQueueUrl` один раз, при старте.

Подписка, которая обрабатывает сообщения по одному, всё равно запрашивает до десяти сообщений за вызов, потому что SQS берёт плату за запросы.
Обработчику она отдаёт их по одному.
Пока обработчик работает, фоновая задача получает следующий пакет и никогда не опережает его больше чем на один пакет.

## Видимость и медленный обработчик {/* #visibility-and-a-slow-handler */}

Полученное сообщение остаётся невидимым для других потребителей на время тайм-аута видимости очереди.
Если к этому времени его не удалили, SQS выдаёт его повторно.
[`visibility`](../components/subscriptions/visibility.md) запрашивает при каждом получении собственный тайм-аут, от одной секунды до двенадцати часов.
SQS считает его в целых секундах, поэтому доля секунды округляется вверх.
`pack` запрашивает минуту.
Без этого шага подписка один раз, при открытии, читает собственный тайм-аут очереди.

Обработчик может работать дольше тайм-аута.
Пока доставка не завершена, крейт продлевает её видимость в середине каждого тайм-аута, поэтому сообщение медленного обработчика не достаётся другому потребителю.
SQS скрывает сообщение не дольше двенадцати часов с момента получения.
Если обработчик работает так долго, крейт продлевает видимость последний раз до конца этих двенадцати часов и пишет предупреждение в журнал, а затем сообщение получает другой потребитель.

## Параллельные обработчики {/* #parallel-handlers */}

`workers(4)` выполняет до четырёх доставок из `orders` одновременно.
Четыре обработчика делят сообщения, которые возвращает каждое получение.
У стандартной очереди нет порядка, который нужно сохранять, поэтому больше ничего не требуется.
[Очереди FIFO](fifo.md) сохраняют порядок группы сообщений с помощью `workers(n, by_key)`.

Обработчик, который принимает срез, - [обработчик пакетов](../components/subscriptions/batches.md).
Размер, заданный в его точке монтирования, становится `MaxNumberOfMessages`, поэтому одно получение - это один пакет.
Пакет содержит то, что было в очереди в этот момент, а длинный опрос, который ничего не вернул, пакета не даёт.
`ReceiveMessage` возвращает не больше десяти сообщений, поэтому больший размер снижается до десяти, и сервис один раз пишет об этом в журнал.
Каждое сообщение пакета завершается отдельно; исходы показывает руководство [Подтверждение](acknowledgement.md).

Шаги очереди тоже задаются в точке монтирования, после шагов самого фреймворка, через [`SqsSubscription`](../components/subscriptions/sqs-subscription.md).
Пустое имя очереди, ожидание дольше 20 секунд или видимость вне допустимого диапазона останавливают сервис при старте с ошибкой [`SqsError::InvalidQueue`](../components/broker/errors.md) ещё до обращения к AWS.
Имя может содержать символы, которых SQS не принимает: каждый символ вне `A-Z`, `a-z`, `0-9`, `_` и `-` заменяется на `-`, а суффикс `.fifo` сохраняется.

[`create_if_missing`](../components/subscriptions/create-if-missing.md) создаёт очередь, которой нет.
Сервис в промышленной эксплуатации обычно получает очереди от своей инфраструктуры и опускает этот шаг; тогда отсутствующая очередь останавливает его при старте.

## Что содержит доставка {/* #what-a-delivery-carries */}

Каждый атрибут сообщения приходит в [доставке](../components/delivery/index.md) заголовком, а каждый заголовок публикации уходит атрибутом.
Два заголовка принадлежат самому крейту.
[`RECEIVE_COUNT_HEADER`](../components/delivery/receive-count.md) хранит счётчик получений сообщения в очереди.
[`PARTITION_KEY_HEADER`](../components/delivery/partition-key.md) хранит группу сообщений очереди FIFO.
Тело SQS - это текст, поэтому двоичная полезная нагрузка передаётся [в кодировке base64](../components/delivery/body.md) с атрибутом-меткой и приходит уже декодированной.
Base64 увеличивает такую нагрузку на треть, а сообщение больше предельного размера SQS отвергает.

Тесты в файле примера публикуют в приложение внутри процесса заказы, платежи и изменения.
Обвязку разбирает руководство [Тестирование сервиса на SQS](testing.md).
